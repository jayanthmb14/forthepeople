# Languages on ForThePeople.in (i18n)

Goal: every word a citizen reads can appear in any of India's 22 scheduled
languages, and switching language changes **everything**. That covers the
header, buttons, labels, dates, numbers, module names, empty states, charts,
alt text and screen-reader text. Nothing citizen-facing is typed in English
inside a component.

This document explains how the system works today, what each kind of text
needs, the layout rules for Indian scripts, and the exact checklist to switch
a new language on.

---

## 1. How it works

```
URL /kn/karnataka/mandya/finance
        │
        ▼
src/proxy.ts ── next-intl middleware: valid locale? planned language → 307 to /en
        │
        ▼
app/[locale]/layout.tsx
  setRequestLocale(locale)            (static rendering, no header reads)
  getMessages({ locale })             ← src/i18n/request.ts
  <NextIntlClientProvider>            (messages for client components)
  <div lang="kn" dir="ltr">           (screen readers, fonts, hyphenation)
        │
        ▼
components: useTranslations("namespace")  →  t("key", { values })
            useFormat()                   →  numbers/dates in kn-IN
            useModuleText()               →  translated module names
```

| Piece | File | Role |
|---|---|---|
| Language registry | `src/i18n/languages.ts` | English plus the 22 scheduled languages: code, native name, script, direction, Intl locale, and status (`live` / `beta` / `planned`). **This is the only list of languages.** |
| Routing | `src/i18n/routing.ts` | Routes = registry languages whose status is not `planned`. |
| Messages | `src/dictionaries/<code>.json` | One JSON file per language, grouped into namespaces. |
| Loader | `src/i18n/request.ts` | Deep-merges a language over English, so a missing key shows English, never a raw key. `TODO_TRANSLATE:` placeholders also fall back. |
| Proxy | `src/proxy.ts` | Redirects `planned` languages to English. The matcher lists no language codes. |
| Language menu | `src/components/common/LanguageMenu.tsx` | Lists routed languages in their own script, marks `beta`, and counts the `planned` ones. It keeps the current page when switching. |
| Client helpers | `src/i18n/client.ts` | `useFormat()` (number, date and time in the language's Intl locale, IST), and `useModuleText()` (module label, description and group). |
| Script → lang code | `src/lib/utils/script-lang.ts` | Tags a local-script name (ಮಂಡ್ಯ) with `lang="kn"`. |

## 2. Rules for every component (the "nothing hard-coded" rule)

1. **No English string literals in JSX or in values that reach the screen.**
   This includes `aria-label`, `title`, `alt`, `placeholder`, chart labels,
   legend text and empty-state sentences. Put the text in `en.json` under a
   namespace and read it with `useTranslations`.
2. **Use variables, never concatenation.** Write `t("latestFor", { name })`,
   not `"Latest data for " + name`. Word order differs between languages.
3. **Plurals use ICU:** `"{n, plural, one {# story} other {# stories}}"`.
   Languages without plural forms simply write one form.
4. **Rich text uses tags:** `"You are in <b>{district}</b>"` with
   `t.rich("key", { b: (c) => <strong>{c}</strong> })`.
5. **Numbers and dates go through `useFormat()`** (or `Intl` with
   `intlLocale(locale)`). Never call `toLocaleString("en-IN")` for text a
   reader sees. Indian grouping (12,34,567) is kept for every language.
6. **Module names come from `useModuleText()`**, not from
   `SIDEBAR_MODULES[].label`. The registry label is only the English fallback.
7. **Server components** call `useTranslations` if they are synchronous, or
   `getTranslations({ locale, namespace })` if they are async. Pages that
   render translated server components call `setRequestLocale(locale)`
   first, which keeps them statically rendered.
8. **Kit components translate themselves.** `AsOfText`, `FreshnessPill`,
   `PageHeader` (back link, group chip, and the title and description when
   the page passes the registry's English ones), `EmptyState` defaults,
   `ChartCard` and `Explainer` all translate on their own. Old pages that pass
   English prefixes such as "As of", "Updated" or "Recorded" are mapped to
   keys automatically.

## 3. The three kinds of text

| Kind | Examples | Where it lives | How it is translated |
|---|---|---|---|
| **A. Interface text** | buttons, labels, headings, empty states, chart titles | `src/dictionaries/<code>.json` | Translated once per language: an AI draft reviewed by a native speaker (see §6). |
| **B. Reference data** | district and taluk names, state names, taglines, module-specific constants (scheme names, office names) | Registry (`src/lib/constants/districts.ts`) and the database | Needs per-language fields (see below). |
| **C. Live data** | news headlines, AI insights, tender titles, mandi commodity names | Database, refreshed by crons | Shown in the language the source published. AI insights get a per-language generation (see below). |

**B. Reference data, what changes:**

- **District and taluk names.** Today there is one `nameLocal` (the state's
  language). Add a `names` JSON map, e.g. `{"hi": "मंड्या", "ta": "மாண்டியா"}`, to
  the registry entries and a `names Json?` column to `District` and `Taluk`.
  Components pick `names[locale] ?? (scriptLang(nameLocal) === locale ? nameLocal : name)`.
- **State names.** Add a `states.<slug>` namespace to the messages (36 keys).
- **Taglines and badges** (e.g. "Sugar Capital of Karnataka"). Move them to
  messages under `districts.<slug>.tagline`, or add `taglines` JSON on the
  row. They are short and few (under 50 total), so messages are simplest.
- **Commodity names in mandi prices.** Keep a glossary namespace
  `commodities.<normalised-name>` for the ~150 common items. Unknown items
  stay as published.

**C. Live data, what changes:**

- **News.** Show in the original language. Add a "show only news in my
  language" filter once Indian-language feeds are added (the news cron can
  tag `language`).
- **AI insights.** `callAI` gets a `locale` argument. The insight cron
  generates English first, then translations only for languages that are
  `live`, cached per `(module, district, locale)`. Cost rule: run it only
  when `hasDataChanged()` is true and only for live languages. Never
  translate on every page view.
- **Numbers inside data** (rupees, percentages) are formatted at render
  (rule 5), so they need no translation.

## 4. Layout rules for Indian scripts

- **Line height.** Indic scripts have tall stacked vowel signs and
  conjuncts. Headings in Indic scripts get `line-height ≥ 1.35` and body
  `≥ 1.7`. Never clip text vertically: no fixed heights on text, and no
  `overflow: hidden` with a single-line height except where there is a
  `title` fallback.
- **Text length.** Tamil, Malayalam and Telugu strings run 30–60 % longer
  than English. Buttons and tiles must wrap, not truncate. Use `min-width`,
  never a fixed `width`, on anything holding words. Grids use
  `repeat(auto-fill, minmax(…))`.
- **Fonts.** `next/font/local` already loads Noto Sans for Kannada,
  Devanagari, Tamil, Bengali and Telugu. Each script is picked by
  `:lang()` / `unicode-range`. Adding a script means:
  1. drop its Noto woff2 files into `src/fonts/`;
  2. add a `localFont` entry in `src/lib/fonts.ts`;
  3. add it to the font stack.

  Fonts still to add: Gujarati, Gurmukhi, Malayalam, Odia, Ol Chiki,
  Meetei Mayek, and Noto Nastaliq Urdu for Urdu, Kashmiri and Sindhi. Load
  only the scripts of routed languages (`preload: false` for the rest), so
  a 22-language site does not ship 22 fonts to everyone.
- **Right-to-left (Urdu, Kashmiri, Sindhi).** `<div dir="rtl">` is set
  from the registry.
  - Use logical CSS (`margin-inline-start`, `padding-inline`,
    `inset-inline-end`, `text-align: start`) in new code. Physical
    `left` and `right` break in RTL.
  - Icons that point, such as arrows and chevrons, must flip
    (`transform: scaleX(-1)` under `[dir=rtl]`).
  - Charts, numbers, dates and the map stay LTR: wrap them in
    `<span dir="ltr">`.
- **Digits.** Keep Latin digits (the Intl default for these locales). Do
  not switch to native digit systems unless a language community asks.
  Tables and charts must stay comparable.
- **Emoji and pictures** work the same in every language. Pictogram
  captions and `aria-label`s are translated like any other text.
- **Search.** District search matches the English name, `nameLocal` and
  every `names[*]` value, so a person can type "ಮಂಡ್ಯ" or "मंड्या".

## 5. SEO and URLs

- Every routed language has its own URL prefix (`/kn/...`). The sitemap
  (`src/app/sitemap.ts`) and `hreflang` alternates are generated from
  `routing.locales`, so a newly switched-on language appears automatically.
- `planned` languages redirect with a 307 (temporary), so search engines keep
  checking and pick the URL up once the language goes live.
- `<html lang>` is set per request by the locale layout. Page metadata
  (title, description, Open Graph) must come from messages. When converting
  a page, convert its `generateMetadata` too.

## 6. How to add a language (checklist)

1. **Messages.** Copy `src/dictionaries/en.json` to `<code>.json` and
   translate. AI drafts are fine as a start. Mark the file
   `"_meta": {"status": "machine-draft"}`.
2. **Native review.** At least one native speaker reads every namespace on
   the live pages. Civic terms (ಜಿಲ್ಲಾಧಿಕಾರಿ, ಗ್ರಾಮ ಪಂಚಾಯಿತಿ) must match what the
   state government uses. Change `_meta.status` to `reviewed`.
3. **Font.** If the script is new, add its Noto font (§4).
4. **Registry.** In `src/i18n/languages.ts`, set `status: "beta"`. The
   language gets routes, the menu entry and sitemap entries. English fills
   any gaps.
5. **Reference data.** Add `names[<code>]` for districts, taluks and
   states, and the tagline translations.
6. **AI insights.** Add the code to the insight cron's language list (cost:
   one extra call per changed insight).
7. **QA.** Walk the pages below at 375 px and 1440 px and check that nothing
   overflows or clips, and that nothing is still in English:
   - home
   - one district overview
   - three module pages
   - India page
   - support page
8. **Go live.** Set `status: "live"`. The "beta" tag disappears.
